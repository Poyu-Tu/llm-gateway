## 逐頁旁白

### 第 1 頁｜封面

- **畫面上：** 專案名、定位句、三個數字
- **配給：** 16 秒
- **練習本對照：** —

大家好，我是杜柏豫，現職是資安網路工程師。我的專題是 LLM Gateway，一道管理企業 AI 用量、成本和個資的閘道。

### 第 2 頁｜Agenda

- **畫面上：** 六張卡
- **配給：** 8 秒
- **練習本對照：** —

今天主要分六段，其中一半時間會聊技術實踐。

### 第 3 頁｜先講結論

- **畫面上：** 是誰・花多少・送出什麼
- **配給：** 16 秒
- **練習本對照：** 整體：`app/main.py` 的 `chat_endpoint()`

先講結論。我的 Gateway 每次都在回答三個問題：誰在用？花了多少？送出去的有沒有個資？這三個問題，就是今天的主軸。

### 第 4 頁｜想解決的問題

- **畫面上：** 200 位員工的情境；成本歸屬、用量管控、稽核
- **配給：** 24 秒
- **練習本對照：** —

如果公司開放兩百個人用 AI，月底帳單來了，你知道是誰花的嗎？多半不知道。有人寫錯一個迴圈，一個晚上就燒光預算；有人把客戶資料貼進去，事後也查不到。這就是我想解決的問題。

### 第 5 頁｜解決前後

- **畫面上：** 節費、個資、額度三列
- **配給：** 15 秒
- **練習本對照：** —

以前是月底才知道；現在是每一次送出前就知道。像這個 20 倍是單價，實際省多少，等一下用實測數字講。

### 第 6 頁｜解法提綱｜三道關卡

- **畫面上：** 員工 → 閘道 → 模型；管人、管錢、管資料
- **配給：** 20 秒
- **練習本對照：** 管人 `app/auth.py`；管錢 `app/router.py`、`app/quota.py`；管資料 `app/audit.py`

那要怎麼管？就像大樓只有一條總水管，我幫每一戶裝上水表和限流閥。每次呼叫都要先過三關：管人，知道是誰；管錢，知道花多少；管資料，知道送出什麼。

### 第 7 頁｜解法提綱｜雲端架構

- **畫面上：** VPC 每日層、長期層、OpenAI、GitHub Actions
- **配給：** 81 秒
- **練習本對照：** 設定檔分頁：Terraform 兩層

這是放到 AWS 上的樣子，我照著箭頭走一次請求。員工從 ALB 進來，這是唯一的入口，只放我的 IP；ALB 也會一直打 `/health`，確認 Gateway 還活著。這裡用的是 HTTP，因為 Demo 沒有網域、拿不到憑證，正式環境會換成 HTTPS。請求進到 Gateway，它跑在 Fargate 上，放在 Private Subnet，沒有 Public IP，外面找不到它。Gateway 要問 OpenAI，只能從 NAT 這一個出口出去，而且門口有 DNS Firewall，只放行名單上的網域。OpenAI 的答案回到 Gateway 之後，Gateway 先把這筆帳丟進 SQS，確認收到了，才把答案交給員工。Lambda 在背後把帳記進 DynamoDB。這一整圈用 Terraform 建起來，換新版和一鍵拆掉都交給 GitHub Actions；外面灰色的部分放資料，平常不拆。這張圖就是今天的地圖，後面每一段，都會回到這張圖上的某個地方。

### 第 8 頁｜解法提綱｜一次呼叫發生什麼事

- **畫面上：** 11 步流程，紅色是擋下時回的代碼
- **配給：** 47 秒
- **練習本對照：** `chat_endpoint()` 從上讀到下

那我們進到 Gateway 裡面，一次呼叫會走 11 步。上排 6 步是門禁：Key 錯了回 401、額度用完回 429，連資料庫讀不到也是擋下來，不會放行。任何一步擋下，都還沒碰到模型，所以不花錢。綠色的第 4 步之後，送出去的、寫進紀錄的，都是遮罩後的內容。第 6 步我會先在帳本寫一筆 0 元，確定帳本寫得進去才往下走，不要等錢花了，才發現記不了帳。下排 5 步才真的做事。

### 第 9 頁｜解法提綱｜三件事、兩層、一鍵

- **畫面上：** 三個原則、長期層與每日層、一鍵拆除
- **配給：** 24 秒
- **練習本對照：** 設定檔分頁：`destroy.yml`

我們整理一下剛剛的內容：這個 Gateway 外面連不進來、只有一個出口、沒有長期金鑰；用完一鍵拆除，而且只拆得了貼 daily 標籤的資源，資料不會被誤拆。接下來，看它實際跑起來的樣子。

### 第 10 頁｜技術實踐｜Demo Console

- **畫面上：** bob 問設計題；右欄路由決策、本次用量、剩餘額度
- **配給：** 17 秒
- **練習本對照：** `app/static/`；`me()`

跑起來是這樣。bob 問了一題比較題，右邊告訴你：它被送去強模型、花了多少、還剩多少額度。接下來就從節費開始，一個一個看。

### 第 11 頁｜買瓶飲料，不用叫整台貨車幫你送來

- **畫面上：** 簡單題 → luna、複雜題 → sol；20 倍
- **配給：** 30 秒
- **練習本對照：** `app/router.py` 的 `choose_model()`；`app/pricing.py` 的 `cost_micro_usd()`

買一瓶飲料，你不會叫整台貨車送來。像左邊翻一句英文，就交給便宜的模型，花 7 micro-USD；右邊設計一個系統，才交給強模型，花 1,438 micro-USD，兩顆單價差了 20 倍。判斷規則我設計得比較簡單，只看兩件事：超過 300 字，或出現關鍵字。

### 第 12 頁｜省更多很簡單，答對比較難

- **畫面上：** 25.3%；兩個總額；54.5% 的說明；雲端 Grafana
- **配給：** 31 秒
- **練習本對照：** `scripts/routing_eval.py`；`app/metrics.py`

那實際省多少？我準備了 20 題實測，省了 25.3%。其實我可以讓它省到 54%，只要把門檻放寬。但這樣最難那一題也會被丟給便宜模型，答到一半就被截斷，所以我不選。右下是雲端的 Grafana，誰花了多少、被擋了幾次，不用等月底帳單就可以先看到。

### 第 13 頁｜技術實踐｜節費：備援

- **畫面上：** 429 → 改派 luna；SIMULATION 標示
- **配給：** 23 秒
- **練習本對照：** `app/fallback.py` 的 `chat_with_fallback()`

強模型塞車時，我讓它自動改派便宜模型。答案可能簡單一點，但 User 不用重送，紀錄裡也查得到是哪幾筆被換掉。這頁的塞車是模擬的，因為 OpenAI 塞不塞車，我沒辦法說要就要。

### 第 14 頁｜技術實踐｜個資 ①

- **畫面上：** 一句話四種個資 → 回答只剩標籤；4 類
- **配給：** 20 秒
- **練習本對照：** `app/audit.py` 的 `mask_and_detect()`、`luhn_valid()`

那有人把客戶的身分證貼進去呢？Bob 在一句話裡塞了四種假個資，叫 AI 原樣唸一次。它只唸得出標籤，因為號碼在送出去之前，就已經被換掉了。

### 第 15 頁｜技術實踐｜個資 ②

- **畫面上：** 雲端 audit 表：雜湊值、遮罩後摘要
- **配給：** 21 秒
- **練習本對照：** `hash_prompt()`、`make_summary()`

那紀錄裡呢？只留雜湊值，和前 50 個字的摘要。而且我是先遮罩、再截斷；如果先截斷，號碼可能被切成兩半，遮罩就認不出來了。結果拿原本的號碼去搜，零筆。

### 第 16 頁｜技術實踐｜額度

- **畫面上：** carol 額度歸零；停掉資料庫 → 503
- **配給：** 18 秒
- **練習本對照：** `app/quota.py` 的 `is_over_quota()`、`read_used()`；`get_quota()`

那寫錯迴圈的人呢？每個人每個月一份額度，用完就擋，最多只燒掉自己那一份。右下我把資料庫停掉，它回 503：讀不到額度，就不放行。

### 第 17 頁｜額度｜用完就擋

- **畫面上：** 609 → 818 → 1,039 → 429
- **配給：** 19 秒
- **練習本對照：** `seconds_until_next_period()`

這是 alice，上限 1,000，卻用到 1,039，因為我是送出前檢查，不是預扣，最後一題會超過一點點。下一次就回 429，還告訴她下個月 1 號才恢復。

### 第 18 頁｜看不到的地方 ①｜先拆 LiteLLM：兩個靜默錯誤

- **畫面上：** 發現一、發現二、我的修正
- **配給：** 33 秒
- **練習本對照：** `find_model_config()`；`save_charge()`

開源工具也做得到這些，那我多做了什麼？我先把 LiteLLM 拆開來測，找到兩個不會報錯的問題：第一個是價格表沒有的模型，花費會記成 0；第二個是回答送出去、帳還沒寫就當機，那筆帳就不見了。所以我改成：沒有單價就拒絕，先確認帳進了佇列，才回答。

### 第 19 頁｜看不到的地方 ①｜主動告警

- **畫面上：** OK → ALARM、ALARM → OK 兩封信
- **配給：** 18 秒
- **練習本對照：** `report_budget_exhausted()`；設定檔分頁：告警

上一頁的錯不會alert，所以我的錯要能發alert。OpenAI 預算一用完，告警信就寄到我信箱。這次是用測試日誌觸發的，證明這條路是通的。

### 第 20 頁｜大樓僅有一個門，門口有警衛

- **畫面上：** 私有子網 → NAT＋DNS 防火牆 → 名單
- **配給：** 28 秒
- **練習本對照：** 設定檔分頁：DNS 防火牆

Gateway 要出去只能走 NAT，DNS Firewall 只幫名單上的網域查地址。名單不是我猜的，我先讓它只記錄、不擋，跑一個小時，看 Gateway 實際查了哪些網域，再把其他的全部封鎖。我拿 example.com 試，連地址都查不到，還留下一筆紀錄。

### 第 21 頁｜看不到的地方 ②｜一鍵拆除每日層

- **畫面上：** 左：五次拆除的列表（#1 51 秒 → #5 22 分 37 秒）；右：Cost Explorer 10/19～10/29 每日帳單，四次上雲各約 US$0.2～0.3，其他日子 US$0.00
- **配給：** 21 秒
- **練習本對照：** 設定檔分頁：`destroy.yml`

NAT、ALB、Fargate 都按小時算錢，所以用完當天，按一個鍵就拆光。右邊是十天的帳單：四根柱子是四次上雲，每次大約兩毛多美元；沒上雲的日子，帳單是 0。

程式改了，怎麼確定沒改壞？每次推送都要先過三關：444 個測試、掃 image、掃設定檔，沒過就進不了 main。

### 第 23 頁｜看不到的地方 ③｜持續部署

- **畫面上：** 首次部署被攔下、第三次失敗、修正後只換 image
- **配給：** 28 秒
- **練習本對照：** `scripts/check_deploy_plan.py`；設定檔分頁：`deploy.yml`

部署按一下，會不會連整個環境都改掉？所以我規定它只能換 image。第一次刻意在環境還沒建的時候按，計畫要新建 42 個資源，直接被攔下。第三次是真的失敗，少一個唯讀權限；補上之後，3 分多鐘就自動換好。

### 第 24 頁｜看不到的地方 ③｜沒有長期金鑰

- **畫面上：** 從 main 借到角色；別的分支被擋
- **配給：** 25 秒
- **練習本對照：** `app/openai_auth.py` 的 `get_aws_identity_token()`

repo 裡沒有任何金鑰。GitHub 要動 AWS，是拿 OIDC token 換一小時的 role，而且只有 main 換得到，別的分支在 GitHub 這層就被擋。Gateway 呼叫 OpenAI 也一樣，用 AWS 的身分換通行證，沒有金鑰可以外流。

### 第 25 頁｜看不到的地方 ④｜帳不會掉

- **畫面上：** Gateway → SQS → Lambda → DynamoDB；DLQ；三個情境
- **配給：** 29 秒
- **練習本對照：** `app/events.py` 的 `send_event()`；`worker/handler.py`；`app/ledger.py` 的 `record_charge()`

還記得 LiteLLM 先回答、再寫帳，中間當機帳就掉了嗎？我反過來：帳單確認進了 SQS，才回答。後面的 Lambda 一次寫三本帳：明細、額度、稽核，要嘛全寫、要嘛全不寫；同一筆送兩次，也只扣一次。接下來，我故意把兩個地方弄壞給大家看。

### 第 26 頁｜帳不會掉｜① Worker 停工

- **畫面上：** Disabled → 4 題全答；佇列 4 則；軟上限
- **配給：** 22 秒
- **練習本對照：** `process_message()`；`is_duplicate()`

我把 SQS 觸發 Lambda 的開關關掉，alice 連問四題，每題都有回答，帳單在佇列裡等。重新打開，同一秒四筆一起入帳。代價是這段時間門禁看不到新的帳，User 可能多用一點。
