## 0. 三十秒版（給非技術讀者）

- **做出了什麼：** M3 在筆電上跑的「AI 收費櫃檯」，現在搬到 AWS 東京機房，而且**整台機器只有一個出口、出口有人管**：它只能連 OpenAI 和幾個必要的 AWS 服務，其他網站連地址都查不到。
- **雲端沒有放 OpenAI 的密碼：** 櫃檯每次要叫 AI，先向 AWS 要一張 5 分鐘的身分證明，拿去跟 OpenAI 換通行證。沒有長期金鑰，就沒有金鑰可以外流。
- **用完就拆：** 會按小時收費的部分（NAT、負載平衡器、容器）測完當天拆掉，留下的資料表、帳本、映像幾乎不花錢。拆除用 GitHub 上的一個按鈕，按鈕借的是一小時的臨時權限，只能拆貼了「每日」標籤的東西。
- **四張驗收截圖都拍到了（S08～S11）：** 連 OpenAI 成功、連清單外的網站被擋並留下紀錄；容器沒有公開 IP；兩條專用走廊只准特定動作；兩個角色的權限都指定了資源（兩條 AWS 規定不能指定的例外，附理由）。
- **誠實的弱點：** 一鍵拆除第二次實測**失敗**（拆到公開 IP 時權限不夠），當晚手動補拆、確認拆光，隔天修好權限，但「修好後一鍵拆光」要下一次上雲才驗得到；程式直接用 IP 連外，DNS 防火牆擋不到，這次沒有測。
- **花費：** 上雲那一天約 1 小時 50 分，估約 US$0.22，**Cost Explorer 實際約 US$0.29**（多出來的主因是 NAT 計了 3 小時）；OpenAI 約 US$0.02；投入約 27 小時。

## 1. 為什麼做

**M4 要證明：這個閘道放上雲之後，網路與權限的設計經得起檢查。** 決策書 10.2 的十一個環節裡，第 10 環節（網路邊界）、第 11 環節（供應鏈與部署）是「部署者的責任」，現成工具不會幫你做；M4 就是做這兩個環節，加上第 1 環節的 IAM 最小權限。

M0～M3 的經驗，讓 M4 的設計對著四件事做：

1. **只要接外部供應商，就一定有出口。** v2.5 從 Zero Egress 改成受控出口（D25），M4 要拿出「出口真的有人管」的證據（S08），而不是只有架構圖
2. **長期金鑰是最大的外洩點。** M0 刪掉 AWS 的長期金鑰；M4 連 OpenAI 的金鑰都不放上雲（4.5）
3. **雲端很貴的是「忘了關」。** 按小時計費的東西要能一鍵拆光，拆除本身也不能拿萬用鑰匙（6.4）
4. **本機驗過的不等於雲端會動。** 所以上雲前先把容器、稽核、資料庫連線在本機做到跟雲端一樣（開工前準備八項）

**生活比喻：** 開分店。店面（NAT、負載平衡器、容器）按小時租，打烊就退租；戶籍、存摺、帳本（資料表、State、映像）放保險箱。大門口有一位拿名單的總機，名單外的號碼一律不轉接。員工不帶萬用鑰匙，每次刷員工證換臨時通行證；收攤的拆除組也一樣，只能拆貼了「每日」標籤的東西。

## 4. 最重要的一點：沒報錯，不代表做到了

M2 學到「綠燈不代表測到你以為的東西」；M3 學到「數字好看不代表做對了」。M4 再多一層：**雲端的錯，很多是安靜的。** 它不會當掉、不會紅字，只是默默地沒做到。這一關遇到六次：

| 哪一次 | 看起來 | 實際上 | 怎麼發現的 |
|---|---|---|---|
| 舊環境變數 | 43 個測試全部綠燈 | 連到開發用的資料庫，還清空了資料表 | 預期該紅的沒紅，回頭查（E111） |
| IAM 模擬器打錯字 | `implicitDeny`，看起來被擋了 | 根本沒有這個動作；Deny 清單打錯字也是這樣默默失效 | 打錯一次才注意到「不報錯」（E120） |
| AWS CLI 查詢欄位打錯 | 什麼都沒印 | 欄位名稱打錯只會回空的，不是「沒有資料」 | 沒有報錯、什麼都不印，回頭看指令才發現（E123） |
| 容器 `Started`、`Up` | 啟動成功 | 程式在載入設定時就停了 | 看日誌（E114） |
| ALERT 一小時 | 查詢日誌裡完全沒有防火牆欄位，像是沒在運作 | 放行規則判定通過的查詢本來就不記；切 BLOCK 後封鎖紀錄才出現 | 用出口檢查故意去連清單外（E124） |
| **權限模擬器 10 題全對** | destroy 角色權限沒問題 | 真的拆時卡在沒出到的那一題 | 第二次真的按 destroy（E124） |

共同點：**驗證要能「看到它做對」，而不是「沒看到它出錯」。** 所以這一關的每個防線都配一個「故意讓它擋」的實驗：拿掉豁免 Config scan 就紅、沒掛 environment 被 AWS 拒、從分支觸發被 GitHub 擋、刪表被刪除保護擋、改錯 audience 被 OpenAI 擋、連 `example.com` 被 DNS 防火牆擋。

最後一個是本關最大的教訓：**模擬器只回答你問的題目。** 它證明了「該擋的有擋」，但證明不了「該放的都有放」，漏掉的題目只有真的做一次才知道。補救是補題目（第 11、12 題），以及每次 destroy 之後直接問 AWS「還剩什麼」，不只看 workflow 的綠勾。

**生活比喻：** 消防演習的檢查表 10 項全打勾，真的失火時才發現逃生門被鎖住，因為檢查表上沒有「逃生門打不打得開」這一項。檢查表只能證明你想到的事。

**帶到後面的做法：**

1. 每個防線至少一個「故意讓它擋」的實驗，看到它擋才算數
2. 拆除、清理類的動作，做完一定直接問 AWS 剩什麼
3. 模擬器、測試的題目，從「真的會呼叫哪些 API」反推，不只從「我想擋什麼」出發

## 6. 新的取捨決定

M4 期間的定案記在證據紀錄，整理成決策書 v2.10 的 24 項待改與 12.11 的新定案。影響最大的六個：

1. **OpenAI 改用工作負載身分聯盟，雲端不放金鑰。** 不選「先用 SSM 放金鑰、驗收後再升級」：多兩個未知數，但上雲前先用自己的 IAM 使用者打通、定好退路，把風險移到開工前。代價：本機開發仍用金鑰（11/2 到期要換）
2. **Terraform 分兩層：長期層平常不拆，每日層測完就拆。** 不選一層一鍵全拆：每次都要重建表、重灌資料、Key 全部換新。代價：兩層分開 apply，長期層的東西結案時要另外記得清
3. **destroy 角色只認 `Layer=daily` 標籤，刻意不給 `CreateTags`；遇到 AWS 不能指定資源的動作，先找不需要它的做法。** 不選 `ec2:Describe*` 這種萬用字元：一次就過，但動作欄有萬用字元（EC2 的 `Describe` 有上百個）。代價：列漏的要等真的拆才知道（這次就漏了一個）
4. **DNS 防火牆先 ALERT、看實際查詢再切 BLOCK；S08 用一次性任務證明，不開 ECS Exec。** 不選直接 BLOCK：漏一個網域就卡在拉不到映像。不選 ECS Exec：要多開網域與權限，和「出口管很緊」反方向
5. **稽核寫不進去時，回答照給、印一行白名單欄位的日誌、設告警。** 不選回 503：錢已經付給供應商了。代價：補收是手動的，日誌也寫不出去時那一筆就沒了（正式做法是 M5 的 SQS）
6. **映像三個沒有修補版的 HIGH 帶著上雲。** 不選擋下：上游沒有修補，換指紋也修不掉，而且都在用不到的函式；與 CI 只擋「有修補版的」一致。每次建映像時重看

## 7. 限制（誠實記錄）

**網路與出口**

- **程式直接用 IP 連外，DNS 防火牆擋不到，這次沒有測**（7.9 的殘餘風險）
- ALERT 只觀察了約一小時、一種流量（啟動＋聊天）；強模型、降級、限流的路徑沒有走過
- 「網域結尾加點」只確認了語法，有沒有消除假改動要等下一次 apply
- VPC Flow Logs 沒開；主路由表、預設網路 ACL 沒有被 Terraform 認領

**拆除**

- **修好後的一鍵拆光還沒有實測**，下一次上雲（M5 開工）時驗；在那之前每次 destroy 完都要問 AWS
- 標籤條件「擋得住不該拆的東西」只用模擬器驗過，沒有在真的資源上做破壞實驗
- 任務定義用 `skip_destroy`，「帳本是空的」不再代表 AWS 上一點不剩（任務定義不收費，會一版一版累積）

**身分與權限**

- 信任條件看 `sub`，「只准 `main`」在 GitHub 的 environment 設定裡，不在 repo、沒有版本紀錄
- 有 repo 管理權限的人等於能拆每日層；個人專題只有本人一個管理員
- `DisassociateAnyAddress` 能把帳號裡任何公開 IP 從機器上拔下來（刪不掉）；這個帳號只有本專題的 IP

**應用與資料**

- 大部分對話測試走替身，連真的資料庫的是 `integration` 那幾組與容器驗證
- 稽核寫不進去時補收是手動的；告警測試用的是手寫的假日誌，不是 Gateway 真的寫不進去
- 雲端只驗了幾次真實對話；延遲只量了幾次、從台灣量；記憶體只記到最高值
- 映像三個 HIGH 沒有修補版
- 雲端的 alice、bob Key 只存在當時的 PowerShell 變數裡；Key 的雜湊還在 `api_keys` 表

**花費**

- AWS 實際約 US$0.29，比估算的 0.22 多約 32%：估算只算了驗收的 1 小時 50 分，但按小時計費的資源要算「建好到拆掉」整段、不滿一小時進位（NAT 計了 3 小時，見第 8 節）
- OpenAI 這一關的呼叫沒有和後台逐筆對帳
