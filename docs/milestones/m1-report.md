## 0. 三十秒版（給非技術讀者）

- **做出了什麼：** 一個在自己電腦上跑的「AI 收費櫃檯」最小版本。送一句話進去，它會轉給 AI、把回答帶回來，並在帳本記下「誰在什麼時候問了什麼」。
- **重點在帳本怎麼記：** 帳本**不存原文**，只存這句話的「指紋」和前 50 個字的摘要。實際驗收時，用一句超過 50 字的話去問，再到帳本裡搜尋後半句，**搜不到**。
- **怎麼確保品質：** 寫了 17 個自動測試，全部不用真的呼叫 AI、不花錢。這些測試在開發過程中擋下三個錯誤，其中一個是「帳本安靜地少記四個欄位，而使用者完全看不出來」。
- **花費：** 真的呼叫 AI 兩次，共 US$0.0000088；AWS 這一關沒有用到。

## 1. 為什麼做

**M1 要證明：會串接 LLM，而且有可追溯的紀錄**（對應指導老師建議的 Step 1）。

後面每一關都疊在這一關上面：M2 加上身分與額度、M3 加上路由與計費、M4 搬上雲端。所以 M1 除了「能動」，還要先把三件事的地基打好：

1. **稽核的資料模型：** 原文不落地，這個原則從第一行程式就要成立，不能等到 M5 才補
2. **測試的做法：** 呼叫外部付費服務的程式，怎麼在不花錢的前提下測試
3. **安全基線：** 金鑰、版本庫、套件、容器，在放進任何機密之前先把鎖裝好

**生活比喻：** 開餐廳前先做出一道菜，從點餐、送廚房、出餐到記帳走完一遍。菜色只有一道，但出單夾、帳本格式、廚房動線都是之後整間店要沿用的。

## 4. 最重要的一點：測試擋下了「安靜地壞掉」

M1 寫了一個測試，內容就是驗收條件本身：**稽核紀錄有雜湊與摘要，而且找不到原文與模型的回答**。

步驟 7 加上「OpenAI 出錯時的處理」，需要把稽核紀錄拆成兩段組裝：先放共同欄位，成功或失敗再各自補欄位。改寫時把「在原紀錄上新增欄位」寫成了「建立一筆新紀錄」，原本的單號、時間、雜湊、摘要全部不見。

這個錯誤的特性：
- 使用者照樣拿得到回答，畫面上沒有任何異狀
- 稽核檔照樣有寫入，只是每一筆都少四個欄位
- 少了這四欄，稽核紀錄既對不回請求，也無法比對內容

擋下它的是那個驗收測試（`KeyError: 'prompt_hash'`）。**這跟 M0.5 在 LiteLLM 看到的是同一類問題**：價格表缺新模型時花費記成 0，預算安靜失效，沒有任何錯誤訊息（M0／M0.5 報告 B3 第 6 點）。

**生活比喻：** 收銀機照常開抽屜、照常找零，只是發票上沒印日期和編號。當天不會有人發現，月底對帳才知道整疊發票都不能用。

**帶到後面的做法：** 每一關的驗收條件，先寫成測試，再開始寫功能。

## 5. 挫折與解法

| 卡在哪 | 原因 | 怎麼解決 | 學到什麼 | 證據 |
|---|---|---|---|---|
| pytest 找不到 `app` 模組 | 專案不打包，沒有安裝進虛擬環境 | `pyproject.toml` 設 `pythonpath = ["."]` | 選擇不打包的結構，這是已知的代價 | E55 |
| 測試工具跳出棄用警告 | Starlette 的測試用戶端改用 `httpx2` | 查證官方文件後替換 | 換套件前先確認維護者與來源 | E56 |
| commit 訊息拼錯字改不回來 | `main` 已禁止強制推送 | 保留錯字 | 保護規則對自己也生效，這是設計的目的 | E57 |
| 假物件測試寫不出來 | 骨架裡的 `**kwargs` 沒有先解釋 | 補充說明後完成 | 提供骨架時，裡面的新語法也要先講清楚 | E61 |
| `I/O operation on closed file` | `f.write` 少縮排一層，跑到 `with` 區塊外 | 依錯誤訊息的行號自行修正 | 測試第一次抓到真正的錯誤 | E65 |
| `'NoneType' object has no attribute` | 只處理了空回答，沒處理「沒有明細」 | 補上判斷 | 先看到測試失敗，才知道測試有用 | E69 |
| 稽核紀錄少四個欄位 | `record = {...}` 建立新字典，取代了原本的 | 改成逐欄新增 | 見第 4 節 | E69 |
| 連猜三次都錯的 `AssertionError` | 不會讀比對結果 | `-` 是預期值、`+` 是實際值，答案在 `+` 那一行 | 讀錯誤訊息比猜快 | E69 |
| 差點把金鑰寫進 M0.5 的 `.env` | 終端機停在實驗資料夾 | 執行前先貼出目錄確認，退回根目錄 | 不確定就先停下來確認 | E71 |
| `invalid value 'COPY'` | 環境變數的值寫成大寫；Dockerfile 的 `COPY` 是指令，交給 uv 的值要小寫 | 改成小寫 | 錯誤訊息已列出合法值 | E74 |

## 6. 新的取捨決定

M1 期間定案 D33～D40（決策書 12.8），並修訂 D6、D23、D24。最大的三個：

1. **Bedrock 退場（D33）：** 不再保留為切回選項。一條不會實作的備案，只會讓文件同時存在兩套網路設計
2. **薄介面簡化（D23 修訂）：** 原本為了「換供應商」設計的抽象層，簡化成一個函式。留著它的理由只剩「測試不花錢」與「細節集中一處」。**抽象層要有真的需求才做**
3. **工作方式（D40）：** Python 自己寫；Dockerfile 與之後的 Terraform 由骨架改寫，但每一行都要能說明。這是為了同時守住「面試答得出來」與「11/7 交得出來」

## 7. 限制（誠實記錄）

- **遮罩還是空殼：** M1 送往 OpenAI 的是未遮罩的內容，摘要的前 50 字也未遮罩。目前只靠「測試句不含個資」這個人為約束，M2 補上後才真正符合決策書 4.2
- **稽核寫在檔案裡：** 容器停止後紀錄就消失；M2 改成 DynamoDB Local
- **真實呼叫只有兩次，** 都是同一句英文短句；中文輸入、長輸入、拒答、限流都只用假物件測過
- **冷卻期的一次例外：** 容器的 Python 基底映像在建置當下未滿 3 天（差約 14 小時）；評估後當天照做並記錄，M4 推上雲端前再確認 digest 仍然有效（E74）
- **尚未做映像弱點掃描：** Trivy 排在 CI 建立時（10/12 那週）
- **Gateway 的記憶體還沒量：** M0／M0.5 報告列的待辦，M1 沒有執行，移到 M2 開工前
- **沒有身分驗證：** 任何連得到 `127.0.0.1:8000` 的程式都能呼叫；M2 加上 API Key
