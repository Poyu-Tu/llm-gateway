# Part A — M0 前置作業

## A1. 為什麼做

**有成本防護，才開工。** 雲端與 AI 都是「用多少算多少」，測試迴圈寫錯一次就可能燒掉整個預算。所以第一步不是寫程式，而是：

1. 把帳號的門鎖好（身分與金鑰）
2. 把錢包的上限設好（預算與硬上限）
3. 確認真的叫得動模型（否則後面全部白做）

**生活比喻：** 開店前先裝好門鎖、收銀機設好單日上限、確認瓦斯接得通，再開始研究菜單。

# Part B — M0.5 拆解 LiteLLM

## B1. 為什麼做

**在自己寫 Gateway 之前，先拆一個業界成熟的 Gateway，看它在「我接下來也要做的那幾件事」上怎麼做、會在哪裡壞。** 目的有三個：

1. **回答「為什麼不用現成的」：** 指導老師指出，懂行的人第一個問題就是這個。用實測回答，比「我覺得」有說服力。
2. **先踩坑再寫程式：** 在本機花兩個晚上、US$0.0003 找到設計缺口，比 M5 上雲後才發現便宜得多。
3. **檢查部署者的責任：** 現成工具不幫你處理的部分（預設值、對外連線、金鑰保管），正是雲端與資安背景的價值所在。

**生活比喻：** 要開自己的早餐店，開店前先去大型連鎖店打工一週，專看收銀和記帳。結果發現：新品沒建價格，收銀機就算 0 元；帳是打烊才一次登入帳本，中途跳電當天的帳就沒了。回頭一看，自己的開店計畫也有一樣的漏洞，趁還沒開店先改掉。

## B2. 做法

1. **選版：** 依冷卻期規則選 v1.102.0（上架 5 天、未撤回、無未修補 KEV），不追最新版（E11、D27）
2. **驗簽：** 用 digest 驗證 cosign 簽章，確保驗過的就是實際執行的（E11）
3. **強化：** 官方 docker-compose 的 7 項不安全預設值逐項改掉（E13、E14）
4. **破壞測試：** 斷網、關資料庫、不設資料庫、預算 0、強制終止程式，看它怎麼壞（E15～E26）
5. **收尾：** 撤銷實驗金鑰、清掉資料庫、密鑰重新產生（E28）

## B4. 最重要的一點：拆別人的系統，修正了自己的設計

決策書 v2.5 以前的流程圖，把「回答使用者」和「丟計費事件進 SQS」畫成**平行**進行。發現 9 讓我看到：照這樣寫程式，Gateway 在「回答已送出、事件還沒進佇列」的瞬間當機，一樣會掉帳。SQS 只保護**已經進到佇列裡**的事件。

**修正（D31）：** 先確認事件進 SQS，再回答。每次請求多等一次 SQS 寫入（約十幾毫秒，相對模型回應的數秒可忽略），換到「使用者拿到回答 = 帳一定在佇列裡」。M5 故障演練第 4 項會用同樣的強制終止手法驗證。

**生活比喻：** 出餐前先把單據夾進出單夾，再把餐端給客人。多花一秒，換到店員下一秒昏倒也不會漏帳。

## B5. 更正我自己的說法

決策書 v2.2～v2.5 寫「LiteLLM 沒接資料庫時預算會放行，所以本案反其道而行」。實測後發現這把「沒設資料庫」和「資料庫斷線」兩種情境混在一起：斷線時 LiteLLM 也是拒絕（發現 1），跟本案做法相同。v2.5.1 已改寫並保留更正紀錄。

## B6. 挫折與解法

| 卡在哪 | 原因 | 怎麼解決 | 學到什麼 | 證據 |
|---|---|---|---|---|
| Docker Compose 讀不懂 `.env` | Windows PowerShell 5.1 的 `>` 預設寫出 UTF-16 | 改用記事本；後來用 `WriteAllText`（無 BOM 的 UTF-8） | 用檔案大小驗證編碼：157 bytes 對、160 就是有 BOM | E14、E28 |

| 讀出的金鑰長度是 1 不是 35 | `-match` 作用在多行時結果仍是陣列 | `$mk = $mk[0]` 取出字串 | 先驗證長度；「剛好能用」會掩蓋錯誤 | E17 |
| 找不到 `cosign.pub` | 新開的 PowerShell 從家目錄開始 | 先切到 `litellm-lab` 資料夾 | — | E11 |
| 搜尋歷史紀錄找金鑰，誤判一大堆 | `sk-` 字串太短（`flask-image` 也命中） | 改用金鑰格式 `sk-[0-9a-f]{32}` 精準搜尋 → 無輸出 | 用資料格式而不是片段字串來找，跟調校告警規則同理 | E17 |
| **截圖時把三組密鑰拍進去並傳出** | 記事本視窗開著 `.env`，疊在終端機上 | 視同外洩：清掉資料庫、三組全部重新產生，新密鑰全程不上畫面 | 確認 `.env` 只看行數、長度、前綴，不開檔截圖（已寫入決策書 11.5） | E28 |

## B7. 限制（誠實記錄）

- 每個破壞測試只做一次
- 多人同時使用的併發負載沒有測
- 正常關機（`stop`）會不會先把帳寫完、Redis 緩衝能否避免掉帳，沒有測
- 「沒接資料庫時全域預算檢查會被跳過」是官方文件記載，未實測
- 斷網實驗只能證明「價格表下載」消失；不寫日誌的連線要抓封包才看得到，留給 M4 的 DNS 查詢日誌
